## 1. Executive Summary

This document specifies the complete rewrite of the `lauren-ai-chatbot/backend` application from Python (using `lauren-framework` and `lauren-ai`) to Rust (using `agtrs`, `axum`, and `injectable`). The existing backend is a multi-agent banking chatbot featuring four specialized agents (UnauthenticatedCRM, AuthenticatedCRM, BankTransfer, Disputes) with inter-agent handoff, human-in-the-loop approval, LLM-as-judge guardrails, RAG-powered knowledge retrieval, SSE streaming, WebSocket event forwarding, HMAC-based request authentication, and real-time cost tracking.

The Rust rewrite preserves all existing functionality while leveraging Rust's compile-time guarantees, zero-cost abstractions, and the `injectable` crate's DI container for type-safe dependency resolution. The `agtrs` crate provides the agent framework (ReAct loop, tools, guardrails, memory, signals), while `axum` replaces `lauren-framework` as the HTTP/WebSocket server with first-class `injectable` integration via `InjectableState` and `FromRequestParts<S> for Inject<T>`.

**Key benefits of the migration:**

- **Compile-time validation**: The `injectable` crate's `DependencyGraph` and `agtrs-graph`'s `AgentGraphNode` catch circular dependencies, missing bindings, and scope mismatches at link time rather than runtime. The `container!{}` macro can further validate at macro-expansion time.
- **Zero-cost DI**: All dependency resolution is statically dispatched through `T::Provider::provide()`. No runtime reflection, no `TypeId`-based hash maps in the hot path. Singleton instances are stored in typed `OnceCell` fields generated by the `SingletonStore` derive.
- **Type-safe tool calls**: The `#[tool]` macro generates JSON Schema from `param(...)` declarations and produces type-safe parameter extraction. Tool input is always `serde_json::Value` but the extraction code is generated, eliminating manual JSON parsing errors.
- **Memory safety**: No GIL, no reference counting across thread boundaries, no `asyncio.Future` race conditions. `Arc<Mutex<>>` for shared state, `tokio::sync` for async primitives.
- **Performance**: Rust's async runtime (tokio) provides superior concurrency with lower memory per task compared to Python's asyncio. SSE streaming and WebSocket forwarding benefit from Rust's zero-copy I/O.

## 2. Project Goals & Non-Goals

### Goals

1. **Feature parity**: Every Python endpoint, agent, tool, guardrail, and middleware must have a Rust equivalent that produces identical observable behavior.
2. **API compatibility**: All HTTP endpoints (paths, methods, request/response shapes) remain identical so the existing Next.js frontend requires zero changes.
3. **SSE event protocol compatibility**: The SSE event types (`token`, `tool_use`, `break`, `done`, `error`, `guardrail_override`) and their JSON shapes must remain identical.
4. **WebSocket event protocol compatibility**: The WebSocket event forwarding protocol (signal → JSON event) must remain identical.
5. **Security model preservation**: The three-layer security model (HMAC signature verification → authenticated user guard → tool-layer identity enforcement) must be preserved with identical trust-chain semantics.
6. **Compile-time validation**: Leverage `injectable`'s `DependencyGraph` and `agtrs-graph`'s `AgentGraphNode` to catch misconfigurations at compile time.
7. **Idiomatic Rust**: Use `Result<T, E>` for error handling, `impl IntoResponse` for Axum handlers, trait-based polymorphism, and ownership/borrowing instead of garbage collection.

### Non-Goals

1. **Database migration**: The current backend uses an in-memory `BankDatabase`. This rewrite does not add PostgreSQL or any persistent store — the in-memory database is preserved as-is.
2. **Frontend changes**: The Next.js frontend is out of scope. The Rust backend must be a drop-in replacement.
3. **Python interop**: No PyO3, no FFI bridge. This is a clean rewrite.
4. **New agents or tools**: No new agent types or tool types are added. The four existing agents and their tools are migrated as-is.
5. **Horizontal scaling**: The rewrite targets single-instance deployment (matching the current Python behavior). Redis-backed conversation stores or distributed state are future work.

### 4.3 Design Principles

1. **Injectable-first architecture**: Every stateful service is `#[derive(Injectable)]` or `#[injectable_impl]`. The `Container` is the single composition root, wrapped in `AxumState` and passed to `axum::Router::with_state()`. Handlers extract dependencies via `Inject<T>` using `FromRequestParts`.

2. **Agent-as-injectable**: Each agent struct is annotated with both `#[agent(...)]` and `#[injectable]`. The `#[agent]` macro generates the `Agent` trait impl (including lifecycle hooks), while `#[injectable]` generates the DI provider. This allows agents to be resolved from the container and injected into controllers.

3. **Tool-as-injectable**: Tools that need shared state (e.g., `GetBalanceTool` needs `BankDatabase`) use `#[injectable]` and accept dependencies via `Inject<T>` fields. Simple function tools use `#[tool]` alone.

4. **Compile-time validation**: `container!{}` macro validates the full dependency graph at compile time. `agtrs-graph`'s `AgentGraphNode` validates agent-tool bindings at container build time.

5. **Axum-native SSE**: Use `axum::response::sse::Sse` with `tokio_stream` for Server-Sent Events. No custom `EventStream` class needed.

6. **Tokio channels replace asyncio.Future**: The HITL approval pattern uses `tokio::sync::oneshot::Sender/Receiver` instead of `asyncio.Future`. The REST approval endpoint sends via the oneshot sender; the tool awaits the receiver.

7. **Signal bus via tokio::broadcast**: Replace Python's `SignalBus` with `tokio::sync::broadcast` channels. The `EventForwarder` subscribes to the broadcast receiver and forwards events to WebSocket clients.

## 6. Dependency Injection Mapping

### 6.1 Python → Rust DI Pattern Mapping

| Python (`lauren-framework`) | Rust (`injectable`) |
|---|---|
| `@injectable(scope=Scope.SINGLETON)` | `#[injectable_impl]` + `#[constructor]` on struct |
| `@module(imports=, providers=, exports=, controllers=)` | Not needed — `container!{}` is the composition root |
| `LaurenFactory.create(AppModule, ...)` | `container!{ BankDatabase, CryptoService, ... }.await?` then `AxumState::new(container)` |
| Constructor injection (auto-wired) | `#[injectable_impl]` with `#[constructor]` + parameter rewriting |
| `Inject[ServiceType]` in constructor | `Inject<ServiceType>` or `Arc<ServiceType>` in `#[constructor]` params |
| `use_value(provide=..., value=...)` | `DynProvider::sync(\|\| Ok(value))` + `.register()` on `ContainerBuilder` |
| `@controller("/path")` | Axum `Router` with `.route("/path", get(handler))` |
| `@use_guards(GuardA, GuardB)` | Axum middleware layers or `FromRequestParts` extractor guards |
| `@middleware()` | Tower `Service` middleware via `axum::middleware::from_fn` |

### 6.2 No Module System Needed

The Python backend uses a hierarchical `@module()` system because `lauren-framework` requires explicit module registration for DI. In Rust with `injectable`, the `inventory` crate automatically collects all `GraphNode` entries from every `#[derive(Injectable)]` and `#[injectable_impl]` across the entire binary. Therefore:

- **No module structs are needed.** The `container!{}` macro at the composition root is the equivalent of the Python `AppModule`.
- **No `imports`/`exports` are needed.** All injectable types are globally visible via `inventory::iter::<GraphNode>()`.
- **No `controllers` list is needed.** Axum routes are defined imperatively in the `Router` builder.

### 6.3 Composition Root (`container.rs`)

The single composition root replaces all Python `@module()` definitions:

```rust

use hmac::{Hmac, Mac};
use sha2::Sha256;
use injectable::{Inject, injectable_impl, constructor};

type HmacSha256 = Hmac<Sha256>;

pub struct CryptoService {
    secret: Vec<u8>,
}

#[injectable_impl]
impl CryptoService {
    #[constructor]
    fn new(config: Inject<crate::config::AppConfig>) -> Self {
        Self {
            secret: config.payload_secret.as_bytes().to_vec(),
        }
    }
}

impl CryptoService {
    pub fn sign(&self, payload: &[u8]) -> String {
        let mut mac = HmacSha256::new_from_slice(&self.secret).expect("HMAC key length");
        mac.update(payload);
        hex::encode(mac.finalize().into_bytes())
    }

    pub fn verify(&self, payload: &[u8], signature: &str) -> bool {
        let mut mac = HmacSha256::new_from_slice(&self.secret).expect("HMAC key length");
        mac.update(payload);
        mac.verify_slice(&hex::decode(signature).unwrap_or_default()).is_ok()
    }
}
```

## 8. Agent Definitions & Migration

### 8.1 Agent Migration Strategy

Each Python agent class decorated with `@agent(name=, system=, ...)` becomes a Rust struct decorated with `#[agent(...)]` and `#[injectable]`. The Python `on_start`, `on_turn_complete`, `on_tool_result`, `on_finish` lifecycle hooks become methods on the `Agent` trait impl (generated by `#[agent]`, with optional manual overrides).

## 9. Tool Definitions & Migration

### 9.1 Tool Migration Strategy

Python tools decorated with `@tool()` become Rust structs annotated with `#[tool]` and `#[injectable]`. The `#[tool]` proc macro generates the `Tool` trait implementation including JSON Schema generation from `param(...)` declarations. Tools that need shared state (like `BankDatabase`) inject it via `Inject<T>`.

### 9.2 `GetBalanceTool`

**Python**:
```python
@tool()
class GetBalanceTool:
    async def run(self, ctx: ToolContext) -> str:
        auth_uid = ctx.execution_context.request.state.get("user_id")
        if not auth_uid:
            return "Error: User not authenticated"
        balance = await self.db.get_balance(auth_uid)
        return f"Balance: ${balance:.2f}"
```

**Rust** (function-style tool):
```rust
use agtrs::{tool, AgtrsError};
use agtrs_runtime::{ToolContext, ToolResult};
use injectable::Inject;
use crate::banking::db::BankDatabase;

#[tool(
    description = "Get the account balance for the authenticated user",
    param(user_id, description = "The user ID to look up (resolved from auth context)", ty = "string"),
)]
pub async fn get_balance(
    user_id: String,
    ctx: &ToolContext,
) -> Result<String, AgtrsError> {
    // Identity comes from context, NOT from LLM parameters
    let auth_uid = ctx.state()
        .get("user_id")
        .and_then(|v| v.as_str())
        .unwrap_or("");

    if auth_uid.is_empty() {
        return Ok("Error: User not authenticated".into());
    }

    // Resolve BankDatabase from the DI container via ToolContext's ResolveContext
    let db = ctx.resolve_context()
        .resolve::<BankDatabase>()
        .await
        .map_err(|e| AgtrsError::Other(e.to_string()))?;

    match db.get_balance(auth_uid).await {
        Some(balance) => Ok(format!("Balance: ${:.2}", balance)),
        None => Ok("Error: Account not found".into()),
    }
}
```

**Alternative** (struct-style tool with injectable):


### 9.3 `TransferFundsTool`

The most complex tool — requires one-shot HITL approval token:

```rust
#[tool(
    description = "Transfer funds from the authenticated user's account to another user",
    param(to_user, description = "The recipient user ID", ty = "string"),
    param(amount, description = "The amount to transfer", ty = "number"),
)]
pub async fn transfer_funds(
    to_user: String,
    amount: f64,
    ctx: &ToolContext,
) -> Result<String, AgtrsError> {
    let auth_uid = ctx.state()
        .get("user_id")
        .and_then(|v| v.as_str())
        .unwrap_or("")
        .to_string();

    if auth_uid.is_empty() {
        return Ok("Error: User not authenticated".into());
    }

    // Validate one-shot approval token from metadata
    let approval = ctx.metadata()
        .get("transfer_approved")
        .and_then(|v| v.as_object());

    match approval {
        Some(token) if token.get("to_user").and_then(|v| v.as_str()) == Some(&to_user)
                     && token.get("amount").and_then(|v| v.as_f64()) == Some(amount)
                     && !token.get("consumed").and_then(|v| v.as_bool()).unwrap_or(true) =>
        {
            // Token is valid — mark as consumed
            // (consumption is handled by ApprovalService)
            let db = ctx.resolve_context().resolve::<BankDatabase>().await
                .map_err(|e| AgtrsError::Other(e.to_string()))?;
            match db.transfer(&auth_uid, &to_user, amount).await {
                Ok(tx) => Ok(format!("Transfer successful: {}", tx.description)),
                Err(e) => Ok(format!("Transfer failed: {}", e)),
            }
        }
        _ => Ok("Error: Transfer requires prior approval. Use the approval tool first.".into()),
    }
}
```

### 9.6 Handoff Tools

The Python `HandoffTo[AgentA, AgentB]` generic subscripted tool needs special treatment in Rust. Since Rust doesn't have Python-style generic subscripted types, each handoff variant becomes a distinct tool struct:

```rust
use agtrs::tool;
use agtrs_runtime::{Tool, ToolContext, ToolResult, AgtrsError};
use injectable::{Inject, injectable, injectable_impl, constructor};
use crate::agents::active_agent_store::ActiveAgentStore;
use serde_json::json;

/// Handoff from any agent to AuthenticatedCRM
#[tool(
    description = "Hand off the conversation to the Authenticated CRM agent",
    param(reason, description = "Reason for handoff", ty = "string"),
)]
pub async fn handoff_to_crm(
    reason: String,
    ctx: &ToolContext,
) -> Result<String, AgtrsError> {
    let store = ctx.resolve_context().resolve::<ActiveAgentStore>().await
        .map_err(|e| AgtrsError::Other(e.to_string()))?;

    let conversation_id = ctx.state()
        .get("conversation_id")
        .and_then(|v| v.as_str())
        .unwrap_or("default");

    store.set_active_agent(conversation_id, "AuthenticatedCRM").await;
    store.set_pending_summary(conversation_id, &reason).await;

    Ok(format!("Handed off to Authenticated CRM: {}", reason))
}

/// Handoff from UnauthCRM to AuthenticatedCRM (auth-enforced)
#[tool(
    description = "Hand off to the Authenticated CRM agent (requires authentication)",
    param(reason, description = "Reason for handoff", ty = "string"),
)]
pub async fn handoff_to_authenticated_crm(
    reason: String,
    ctx: &ToolContext,
) -> Result<String, AgtrsError> {
    let user_id = ctx.state()
        .get("user_id")
        .and_then(|v| v.as_str())
        .unwrap_or("");

    if user_id.is_empty() {
        return Ok("Cannot hand off to authenticated CRM: user is not authenticated. Ask the user to log in first.".into());
    }

    let store = ctx.resolve_context().resolve::<ActiveAgentStore>().await
        .map_err(|e| AgtrsError::Other(e.to_string()))?;
    let conversation_id = ctx.state()
        .get("conversation_id")
        .and_then(|v| v.as_str())
        .unwrap_or("default");

    store.set_active_agent(conversation_id, "AuthenticatedCRM").await;
```

### 9.7 `ApprovalTool`

The HITL approval tool uses `tokio::sync::oneshot` instead of `asyncio.Future`:

```rust
use crate::approval::service::ApprovalService;
use tokio::sync::oneshot;
use serde_json::json;

#[tool(
    description = "Request user approval for a pending action (e.g., fund transfer)",
    param(action_type, description = "Type of action requiring approval", ty = "string"),
    param(details, description = "JSON details of the action", ty = "string"),
)]
pub async fn request_approval(
    action_type: String,
    details: String,
    ctx: &ToolContext,
) -> Result<String, AgtrsError> {
    let conversation_id = ctx.state()
        .get("conversation_id")
        .and_then(|v| v.as_str())
        .unwrap_or("default")
        .to_string();

    let auth_uid = ctx.state()
        .get("user_id")
        .and_then(|v| v.as_str())
        .unwrap_or("")
        .to_string();

        .map_err(|e| AgtrsError::Other(e.to_string()))?;

    let (tx, rx) = oneshot::channel();

    store.create_pending_approval(
        &conversation_id,
        &auth_uid,
        &action_type,
        serde_json::from_str(&details).unwrap_or_default(),
        tx,
    ).await;

    // Emit signal for WebSocket forwarding
    // (handled by ApprovalService internally)

    // Wait up to 30 seconds for approval
    match tokio::time::timeout(
        std::time::Duration::from_secs(30),
        rx,
    ).await {
        Ok(Ok(true)) => Ok("Approval granted. You may proceed with the action.".into()),
        Ok(Ok(false)) => Ok("Approval denied by the user. Do not proceed.".into()),
        Ok(Err(_)) => Ok("Approval request was cancelled.".into()),
        Err(_) => {
            store.cancel_approval(&conversation_id).await;
            Ok("Approval request timed out after 30 seconds.".into())
        }
    }
}
```

### 9.8 Tool Identity Enforcement

A critical security invariant: **tool identity is NEVER LLM-supplied**. Every privileged tool reads `user_id` from the `ToolContext.state()` which flows from the request's HMAC-verified signature. The `ToolContext.state()` is a `HashMap<String, serde_json::Value>` populated by the `SignatureGuard` middleware and propagated through `AgentContext` → `ToolContext`.

This must be enforced in code review and verified by integration tests. No tool should ever accept a `user_id` parameter from the LLM's tool call input — only from `ctx.state()`.

## 10. Guardrail Definitions & Migration

### 10.1 `LLMScopeGuard`

The Python `LLMScopeGuard` is an output guardrail that uses a secondary LLM call as a judge. It sends the agent's response to a judge LLM with the agent's role and allowed scope; the judge answers YES (pass) or NO (block). When blocked, the action is `modify` — replacing the out-of-scope response with a redirect message.

**Rust implementation**:

```rust
use agtrs::{guardrail, Guardrail, GuardrailContext, GuardrailDecision, OutputGuardrail};
use agtrs_runtime::{LlmProvider, Message, Role, LlmOptions, AgtrsError};
use injectable::{Inject, injectable, injectable_impl, constructor};
use async_trait::async_trait;

#[guardrail(kind = "output")]
#[injectable]
pub struct LlmScopeGuard {
    #[injectable(inject)]
    llm: Inject<dyn LlmProvider>,
}

impl LlmScopeGuard {
    /// Evaluate whether the response is within the agent's allowed scope
    async fn judge(
        &self,
        agent_name: &str,
        agent_scope: &str,
        response: &str,
    ) -> Result<bool, AgtrsError> {
        let judge_prompt = format!(
            "You are a scope compliance judge. The agent '{}' has the following scope: '{}'\n\n\
             Is the following response within this agent's scope? Answer YES or NO only.\n\n\
             Response: {}",
            agent_name, agent_scope, response
        );

        let messages = vec![Message::user(&judge_prompt)];
        let options = LlmOptions::new()
            .temperature(0.0)
            .max_tokens(10);

        let result = self.llm.complete(&messages, &options).await?;
        let answer = result.content.to_text().to_uppercase().trim().to_string();

        Ok(answer.starts_with("YES"))
    }
}

#[async_trait]
impl OutputGuardrail for LlmScopeGuard {
    async fn check(
        &self,
        response: &Message,
        context: &GuardrailContext,
    ) -> Result<GuardrailDecision, AgtrsError> {
        let agent_scope = match context.agent_name.as_str() {
            "AuthenticatedCRM" => "Authenticated CRM Agent — can use banking tools, initiate transfers/disputes, check auth. Redirects to public assistant for product info.",
            "BankTransfer" => "Transfer Agent — only gather transfer details, request approval, execute transfer. Redirects to CRM for anything else.",
            "Disputes" => "Disputes Agent — only review transactions, gather dispute info, handoff. Redirects to CRM for anything else.",
            _ => return Ok(GuardrailDecision::Pass),
        };

        let response_text = response.content.to_text();
        let in_scope = self.judge(&context.agent_name, agent_scope, &response_text).await?;

        if in_scope {
            // Emit GuardrailTriggered signal for "pass" case
            Ok(GuardrailDecision::Pass)
        } else {
            let redirect = format!(
                "I'm not able to help with that request. Let me redirect you to the appropriate assistant."
            );
            Ok(GuardrailDecision::Modify(Message::assistant(&redirect)))
        }
    }
}

#[async_trait]
impl Guardrail for LlmScopeGuard {
    fn name(&self) -> &str { "llm_scope_guard" }

    async fn check_output(
        &self,
        response: &Message,
        context: &GuardrailContext,
```

### 12.3 Guard Implementation as Axum Middleware

Python's `@use_guards()` is replaced by Axum middleware or `FromRequestParts` extractors:

```rust
// SignatureGuard as middleware
use axum::{
    extract::Request,
    middleware::Next,
    response::{IntoResponse, Response},
    http::StatusCode,
};

pub async fn signature_guard(
    Inject(crypto): Inject<CryptoService>,
    mut request: Request,
    next: Next,
) -> Result<Response, StatusCode> {
    let signature = request.headers()
        .get("X-Signature")
        .and_then(|v| v.to_str().ok())
        .ok_or(StatusCode::UNAUTHORIZED)?;

    let body = axum::body::to_bytes(request.into_body(), 1024 * 1024)
        .await
        .map_err(|_| StatusCode::BAD_REQUEST)?;

    if !crypto.verify(&body, signature) {
        return Err(StatusCode::UNAUTHORIZED);
    }

    // Parse user_id from verified body and attach to request extensions
    let parsed: serde_json::Value = serde_json::from_slice(&body)
        .map_err(|_| StatusCode::BAD_REQUEST)?;
    let user_id = parsed.get("user_id")
        .and_then(|v| v.as_str())
        .unwrap_or("")
        .to_string();

    // Reconstruct request with body and extensions
    let mut request = Request::new(axum::body::Body::from(body));
    request.extensions_mut().insert(UserIdExtension(user_id));

    Ok(next.run(request).await)
}

// AuthenticatedUserGuard as middleware
pub async fn authenticated_user_guard(
    request: Request,
    next: Next,
) -> Result<Response, StatusCode> {
    let user_id = request.extensions()
        .get::<UserIdExtension>()
        .map(|e| e.0.as_str())
        .unwrap_or("");

    if user_id.is_empty() {
        return Err(StatusCode::UNAUTHORIZED);
    }

    Ok(next.run(request).await)
}

// Extension type for request-scoped data
#[derive(Debug, Clone)]
pub struct UserIdExtension(pub String);
```

### 13.2 Multi-Agent Handoff Loop with SSE

The Python controller implements a loop: run active agent → check for handoff → run next agent → repeat (up to 8 times for authenticated, 4 for public). This must be preserved:

```rust
// chat/orchestration.rs

pub async fn run_multi_agent_chat(
    conversation_id: String,
    message: String,
    is_authenticated: bool,
    user_id: Option<String>,
    resolve_ctx: Arc<ResolveContext>,
) -> impl Stream<Item = Result<Event, Infallible>> {
    let max_handoffs = if is_authenticated { 8 } else { 4 };

    async_stream::stream! {
        let active_agent_store = resolve_ctx.resolve::<ActiveAgentStore>().await.unwrap();
        let mut current_agent_name = active_agent_store
            .get_active_agent(&conversation_id)
            .await
            .unwrap_or_else(|| {
                if is_authenticated { "AuthenticatedCRM".into() }
                else { "UnauthenticatedCRM".into() }
            });

        for handoff_count in 0..=max_handoffs {
            // Resolve the agent from the container
            let (agent, mut ctx) = resolve_agent(&current_agent_name, &resolve_ctx, &conversation_id, &user_id).await;

            // Build input
            let input = if handoff_count > 0 {
                let summary = active_agent_store.get_and_clear_summary(&conversation_id).await
                    .unwrap_or_default();
                Message::user(&format!("[HANDOFF from {}]: {}", current_agent_name, summary))
            } else {
                Message::user(&message)
            };

            // Run agent with streaming
            let mut stream = agent.run_stream(input, &mut ctx).await;

            while let Some(event) = stream.next().await {
                match &event {
                    StreamEvent::Done(_) => { /* fall through to handoff check */ }
                    _ => { /* forward to SSE */ }
                }
                yield map_stream_event_to_sse(event);
            }

            // Check for handoff
            let new_agent = active_agent_store.get_active_agent(&conversation_id).await;
            if new_agent.as_deref() == Some(&current_agent_name) || new_agent.is_none() {
                break; // No handoff occurred
            }

            // Emit "break" SSE event for frontend
            yield Ok(Event::default().event("break").data("{}"));

            current_agent_name = new_agent.unwrap();
        }
    }
}
```

### 13.3 WebSocket Gateway

```rust
use axum::{
    extract::ws::{WebSocket, WebSocketUpgrade, Message as WsMessage},
    extract::State,
};
use injectable::Inject;

pub async fn ws_handler(
    ws: WebSocketUpgrade,
    Query(params): Query<HashMap<String, String>>,
    Inject(token_service): Inject<WsTokenService>,
    Inject(event_forwarder): Inject<EventForwarder>,
) -> impl IntoResponse {
    // Verify token
    let token = params.get("token").unwrap_or(&String::new()).clone();
    let user_id = match token_service.verify_token(&token).await {
        Some(uid) => uid,
        None => return StatusCode::UNAUTHORIZED.into_response(),
    };

    ws.on_upgrade(move |socket| handle_ws(socket, user_id, event_forwarder))
}

async fn handle_ws(mut socket: WebSocket, user_id: String, forwarder: EventForwarder) {
    // Subscribe to signal bus for this user
    let mut rx = forwarder.subscribe(&user_id).await;

    // Forward events to WebSocket
    tokio::spawn(async move {
        while let Ok(event) = rx.recv().await {
            let json = serde_json::to_string(&event).unwrap_or_default();
            if socket.send(WsMessage::Text(json.into())).await.is_err() {
                break;
            }
        }
    });

    // Read incoming messages (ping/pong, close)
    while let Some(msg) = socket.recv().await {
        match msg {
            Ok(WsMessage::Close(_)) => break,
            _ => {}
        }
    }
}
```

### 13.4 `WsTokenService`

```rust
use injectable::{Inject, injectable_impl, constructor};
use crate::crypto::service::CryptoService;
use base64::{Engine, engine::general_purpose::URL_SAFE_NO_PAD};
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
struct WsTokenPayload {
    sub: String,   // user_id
    iat: u64,      // issued at (unix timestamp)
    exp: u64,      // expiry (unix timestamp)
}

pub struct WsTokenService {
    crypto: CryptoService,  // Injected, but we need owned for Send
}

#[injectable_impl]
impl WsTokenService {
    #[constructor]
    fn new(crypto: Inject<CryptoService>) -> Self {
        Self { crypto: crypto.into_inner() }
    }
}

impl WsTokenService {
    pub fn create_token(&self, user_id: &str, ttl_secs: u64) -> String {
        let now = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap()
            .as_secs();

        let payload = WsTokenPayload {
            sub: user_id.to_string(),
            iat: now,
            exp: now + ttl_secs,
        };

        let json = serde_json::to_string(&payload).unwrap();
        let encoded = URL_SAFE_NO_PAD.encode(json.as_bytes());
        let signature = self.crypto.sign(encoded.as_bytes());

        format!("{}.{}", encoded, signature)
    }

    pub fn verify_token(&self, token: &str) -> Option<String> {
        let parts: Vec<&str> = token.splitn(2, '.').collect();
        if parts.len() != 2 {
            return None;
        }

        if !self.crypto.verify(parts[0].as_bytes(), parts[1]) {
            return None;
        }

        let json = URL_SAFE_NO_PAD.decode(parts[0]).ok()?;
        let payload: WsTokenPayload = serde_json::from_slice(&json).ok()?;

        let now = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap()
            .as_secs();

        if now > payload.exp {
            return None;
        }

        Some(payload.sub)
    }
}
```

## 14. Authentication & Authorization Migration

### 14.1 Three-Layer Security Model

The Python backend implements a three-layer security model that must be preserved exactly:

| Layer | Python | Rust |
|---|---|---|
| **1. HMAC Signature** | `SignatureGuard` verifies `X-Signature` header, pins `user_id` to `request.state` | `signature_guard` middleware verifies HMAC, inserts `UserIdExtension` into `request.extensions()` |
| **2. Auth Check** | `AuthenticatedUserGuard` rejects if `request.state.user_id` is empty | `authenticated_user_guard` middleware rejects if `UserIdExtension` is missing or empty |
| **3. Tool Identity** | Every privileged tool reads identity from `ctx.execution_context.request.state.user_id` | Every privileged tool reads identity from `ToolContext.state().get("user_id")` which flows from `request.extensions()` through `AgentContext` to `ToolContext` |

### 14.2 Identity Propagation Chain

```
HTTP Request
    │
    ▼
SignatureGuard middleware
    │  Verifies X-Signature HMAC
    │  Parses body JSON, extracts user_id
    │  Inserts UserIdExtension(user_id) into request.extensions()
    ▼
AuthenticatedUserGuard middleware (optional)
    │  Rejects if UserIdExtension is missing/empty
    ▼
Chat Handler
    │  Reads user_id from request.extensions().get::<UserIdExtension>()
    │  Populates AgentContext.state with {"user_id": ..., "conversation_id": ...}
    ▼
AgentExecutor (ReAct Loop)
    │  Passes AgentContext to ToolContext on each tool call
    ▼
Tool
    │  Reads user_id from ToolContext.state().get("user_id")
    │  NEVER reads user_id from LLM-supplied parameters
    ▼
```

### 15.1 Signal Bus Architecture

Python's `SignalBus` is a type-erased event bus. In Rust, we use `tokio::sync::broadcast`:

```rust
use tokio::sync::broadcast;
use serde::Serialize;

#[derive(Debug, Clone, Serialize)]
#[serde(tag = "type")]
pub enum AppSignal {
    ModelCallComplete {
        model: String,
        usage: TokenUsage,
        cost_usd: f64,
        conversation_id: String,
    },
    AgentTurnComplete {
        agent_name: String,
        turn: u32,
        conversation_id: String,
    },
    ToolCallStarted {
        tool_name: String,
        conversation_id: String,
    },
    ToolCallComplete {
        tool_name: String,
        duration_ms: u64,
        conversation_id: String,
    },
    GuardrailTriggered {
        agent_name: String,
        passed: bool,
        conversation_id: String,
    },
    ToolPendingApproval {
        conversation_id: String,
        action_type: String,
        details: serde_json::Value,
    },
    AgentRunComplete {
        agent_name: String,
        conversation_id: String,
    },
}

pub struct AppSignalBus {
    sender: broadcast::Sender<AppSignal>,
}

#[injectable_impl]
impl AppSignalBus {
    #[constructor]
    fn new() -> Self {
        let (sender, _) = broadcast::channel(256);
        Self { sender }
    }
}

impl AppSignalBus {
    pub fn emit(&self, signal: AppSignal) {
        // Ignore send errors (no receivers is fine)
        let _ = self.sender.send(signal);
    }

    pub fn subscribe(&self) -> broadcast::Receiver<AppSignal> {
        self.sender.subscribe()
    }
}
```

### 15.2 `EventForwarder`

The `EventForwarder` subscribes to the signal bus and routes events to the correct WebSocket connections:

```rust
use std::collections::HashMap;
use std::sync::Arc;
use tokio::sync::{Mutex, broadcast};
use injectable::{Inject, injectable_impl, constructor};

pub struct EventForwarder {
    bus: AppSignalBus,
    // Map user_id → Vec<broadcast::Sender<WsEvent>>
    // (each WS connection gets its own sender)
    connections: Arc<Mutex<HashMap<String, Vec<tokio::sync::mpsc::Sender<WsEvent>>>>>,
}

#[injectable_impl]
impl EventForwarder {
    #[constructor]
    fn new(bus: Inject<AppSignalBus>) -> Self {
        Self {
            bus: bus.into_inner(),
            connections: Arc::new(Mutex::new(HashMap::new())),
        }
    }
}

impl EventForwarder {
    pub async fn subscribe(&self, user_id: &str) -> broadcast::Receiver<AppSignal> {
        self.bus.subscribe()
    }

    pub async fn register_connection(&self, user_id: &str, tx: tokio::sync::mpsc::Sender<WsEvent>) {
        self.connections.lock().await
            .entry(user_id.to_string())
            .or_default()
            .push(tx);
    }

    pub async fn unregister_connection(&self, user_id: &str, tx_id: usize) {
        // Remove the specific connection
    }

    /// Forward signals to WebSocket connections for a specific user
    pub async fn start_forwarding(self: Arc<Self>) {
        let mut rx = self.bus.subscribe();
        while let Ok(signal) = rx.recv().await {
            let ws_event = match &signal {
                AppSignal::ModelCallComplete { .. } => WsEvent::from_signal(&signal),
                AppSignal::ToolCallStarted { .. } => WsEvent::from_signal(&signal),
                AppSignal::ToolPendingApproval { conversation_id, .. } => {
                    // Route to the user who owns this conversation
                    WsEvent::from_signal(&signal)
                }
                _ => continue,
            };

            // Route to correct user's connections
            let user_id = signal.conversation_id().split(':').next().unwrap_or("");
            let conns = self.connections.lock().await;
            if let Some(senders) = conns.get(user_id) {
                for sender in senders {
                    let _ = sender.send(ws_event.clone()).await;
                }
            }
        }
    }
}
```

## 18. Human-in-the-Loop Approval Migration

### 18.1 `ApprovalService`

Replace Python's `asyncio.Future` with `tokio::sync::oneshot`:

```rust
use std::collections::HashMap;
use tokio::sync::{Mutex, oneshot};
use injectable::{Inject, injectable_impl, constructor};
use serde_json::Value;

pub struct PendingApproval {
    pub user_id: String,
    pub action_type: String,
    pub details: Value,
    pub created_at: std::time::Instant,
    pub responder: oneshot::Sender<bool>,
}

pub struct ApprovalService {
    pending: Mutex<HashMap<String, PendingApproval>>,
    bus: Inject<AppSignalBus>,
}

#[injectable_impl]
impl ApprovalService {
    #[constructor]
    fn new(bus: Inject<AppSignalBus>) -> Self {
        Self {
            pending: Mutex::new(HashMap::new()),
            bus,
        }
    }
}

impl ApprovalService {
    pub async fn create_pending_approval(
        &self,
        conversation_id: &str,
        user_id: &str,
        action_type: &str,
        details: Value,
        responder: oneshot::Sender<bool>,
    ) {
        self.pending.lock().await.insert(
            conversation_id.to_string(),
            PendingApproval {
                user_id: user_id.to_string(),
                action_type: action_type.to_string(),
                details,
                created_at: std::time::Instant::now(),
                responder,
            },
        );

        // Emit signal for WebSocket forwarding
        self.bus.emit(AppSignal::ToolPendingApproval {
            conversation_id: conversation_id.to_string(),
            action_type: action_type.to_string(),
            details: details.clone(),
        });
    }

    pub async fn respond(&self, conversation_id: &str, approved: bool) -> Result<(), String> {
        let mut pending = self.pending.lock().await;
        if let Some(mut entry) = pending.remove(conversation_id) {
            // Check 60-second expiry
            if entry.created_at.elapsed().as_secs() > 60 {
                return Err("Approval request expired".into());
            }

            entry.responder.send(approved)
                .map_err(|_| "Failed to send approval response".to_string())
        } else {
            Err("No pending approval found".into())
        }
    }

    pub async fn cancel_approval(&self, conversation_id: &str) {
        self.pending.lock().await.remove(conversation_id);
    }
}
```

### 18.3 One-Shot Approval Token Pattern

The Python `TransferFundsTool` validates a one-shot approval token from `agent_context.metadata["transfer_approved"]`. The token contains `to_user`, `amount`, and `consumed` flag. In Rust:

```rust
// After ApprovalTool receives approval, set metadata on AgentContext:
ctx.metadata_mut().insert(
    "transfer_approved".into(),
    serde_json::json!({
        "to_user": to_user,
        "amount": amount,
        "consumed": false,
        "timestamp": chrono::Utc::now().timestamp(),

    Some(token) if !token["consumed"].as_bool().unwrap_or(true)
                 && token["to_user"].as_str() == Some(&to_user)
```

## 19. Multi-Agent Routing & Handoff Migration

### 19.1 Handoff Flow

The Python controller implements a multi-step handoff loop:

1. Read `ActiveAgentStore.get(conversation_id, default_agent)` to determine current agent
2. Run the active agent via `runner.run_stream(...)` → yield SSE chunks
3. After agent completes, check if `ActiveAgentStore` changed (i.e., agent called `HandoffTo`)
4. If changed, emit `break` SSE event, retrieve pending summary, construct new prompt with `[HANDOFF from X]: summary`, and loop
5. Maximum 8 handoffs for authenticated, 4 for public

This entire logic is implemented in `chat/orchestration.rs` (see Section 13.2 for the full implementation).

### 19.2 Agent Resolution from Container

```rust
async fn resolve_agent(
    agent_name: &str,
    resolve_ctx: &ResolveContext,
    conversation_id: &str,
    user_id: &Option<String>,
) -> (Arc<dyn Agent>, AgentContext) {
    let (agent, ctx) = match agent_name {
        "UnauthenticatedCRM" => {
            let agent = resolve_ctx.resolve::<UnauthenticatedCrmAgent>().await.unwrap();
            let llm = resolve_ctx.resolve_external::<Arc<dyn LlmProvider>>().await.unwrap();
            let store = resolve_ctx.resolve::<UnauthCrmStore>().await.unwrap();
            let guardrails: Vec<Arc<dyn Guardrail>> = vec![];
            let mut ctx = AgentContext::new(
                agent_name,
                agent.config().clone(),
                llm,
                Arc::new(resolve_ctx.clone()),
            );
            ctx.set_conversation_store(Arc::new(store.0.clone()));
            (Arc::new(agent) as Arc<dyn Agent>, ctx)
        }
        "AuthenticatedCRM" => {
            let agent = resolve_ctx.resolve::<AuthenticatedCrmAgent>().await.unwrap();
            let llm = resolve_ctx.resolve_external::<Arc<dyn LlmProvider>>().await.unwrap();
            let store = resolve_ctx.resolve::<AuthCrmStore>().await.unwrap();
            let guardrail = resolve_ctx.resolve::<LlmScopeGuard>().await.unwrap();
            let guardrails: Vec<Arc<dyn Guardrail>> = vec![Arc::new(guardrail)];
            let mut ctx = AgentContext::new(
                agent_name,
                agent.config().clone(),
                llm,
                Arc::new(resolve_ctx.clone()),
            );
            ctx.set_conversation_store(Arc::new(store.0.clone()));
            for g in guardrails {
                ctx.add_guardrail(g);
            }
            (Arc::new(agent) as Arc<dyn Agent>, ctx)
        }
        "BankTransfer" => {
            // Similar to AuthenticatedCRM, with LlmScopeGuard
        }
        "Disputes" => {
            // Similar to AuthenticatedCRM, with LlmScopeGuard
        }
        _ => panic!("Unknown agent: {}", agent_name),
    };

    // Populate context with user_id and conversation_id
    if let Some(uid) = user_id {
        ctx.state_mut().insert("user_id", serde_json::json!(uid));
    }
    ctx.state_mut().insert("conversation_id", serde_json::json!(conversation_id));

    (agent, ctx)
}
```

## 21. Error Handling Strategy

### 21.1 Error Type Hierarchy

The Rust rewrite uses a layered error approach:

| Layer | Error Type | Conversion |
|---|---|---|
| DI / Container | `InjectableError` | Via `AgtrsError::InjectableError` |
| Agent Runtime | `AgtrsError` | Direct use |
| HTTP Handlers | `axum::http::StatusCode` or custom `AppError` | Via `IntoResponse` |
| Tools | `AgtrsError` | Returned from `Tool::call()` |
| Database | Custom `String` errors | Via `AgtrsError::Other` |

### 21.2 Custom `AppError` for HTTP Responses

```rust
use axum::http::StatusCode;
use axum::response::{IntoResponse, Response};
use axum::Json;
use serde_json::json;

pub enum AppError {
    Unauthorized(String),
    BadRequest(String),
    Internal(String),
    Agtrs(AgtrsError),
    Injectable(InjectableError),
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        let (status, message) = match self {
            AppError::Unauthorized(msg) => (StatusCode::UNAUTHORIZED, msg),
            AppError::BadRequest(msg) => (StatusCode::BAD_REQUEST, msg),
            AppError::Internal(msg) => (StatusCode::INTERNAL_SERVER_ERROR, msg),
            AppError::Agtrs(e) => (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()),
            AppError::Injectable(e) => (StatusCode::INTERNAL_SERVER_ERROR, e.to_string()),
        };

        (status, Json(json!({"error": message}))).into_response()
    }
}

impl From<AgtrsError> for AppError {
    fn from(e: AgtrsError) -> Self { AppError::Agtrs(e) }
}

impl From<InjectableError> for AppError {
    fn from(e: InjectableError) -> Self { AppError::Injectable(e) }
}
```

```rust
    let response = client.send("How do I hack a bank?").await.unwrap();

    // Guardrail should have blocked or modified this response
    assert!(response.content.to_text().contains("redirect")
         || response.content.to_text().contains("can't help"));
}
```

## 24. Risk Assessment & Mitigation

### 24.1 High Risks

| Risk | Impact | Likelihood | Mitigation |
|---|---|---|---|
| **SSE protocol mismatch** | Frontend breaks | Medium | Write integration tests that compare SSE output byte-for-byte with Python backend |
| **Handoff loop race conditions** | Wrong agent activated | Medium | Use `tokio::sync::Mutex` for `ActiveAgentStore`, test with concurrent handoffs |
| **LLM provider compatibility** | Agent responses differ | Medium | Use same model, same prompts, same temperature; add prompt regression tests |
| **HMAC timing attacks** | Security vulnerability | Low | Use constant-time comparison (`hmac` crate does this by default) |

### 24.2 Medium Risks

| Risk | Impact | Likelihood | Mitigation |
|---|---|---|---|
| **`inventory` crate global collection** | Test isolation failures | Medium | Use `--test-threads=1` or accept 4 known inventory-related test failures (same as `injectable` crate) |
| **WebSocket backpressure** | Event loss | Low | Use `broadcast::channel(256)` with overflow policy; frontend must handle missed events |
| **Guardrail LLM judge latency** | Slow responses | Medium | Cache judge responses for identical inputs; consider local keyword guardrail as fallback |
| **Tool context propagation** | Missing user_id in tools | Medium | Centralized `populate_agent_context()` function; integration tests verify user_id in every tool call |

### 24.3 Low Risks

| Risk | Impact | Likelihood | Mitigation |
|---|---|---|---|
| **Axum breaking changes** | Migration needed | Low | Pin `axum = "0.8"` in Cargo.toml |
| **Compile times** | Slow development | High | Use `cargo check` for iteration; split into multiple crates for parallel compilation |
| **Missing Python feature parity** | Feature gap discovered | Low | Comprehensive PRD review against Python codebase; phased delivery with feature parity checks |

## Appendix B: SSE Event Protocol Specification

The following SSE event types must be preserved identically for frontend compatibility:

### `token` event
```
event: token
data: {"content": "Hello"}
```

### `tool_use` event
```
event: tool_use
data: {"tool": "get_balance"}
```

### `break` event (handoff)
```
event: break
data: {}
```

### `done` event
```
event: done
data: {"turns": 3, "tool_calls": 1}
```

### `error` event
```
event: error
data: {"error": "LLM call failed: rate limit"}
```

### `guardrail_override` event
```
event: guardrail_override
data: {"message": "I'm not able to help with that. Let me redirect you."}
```
